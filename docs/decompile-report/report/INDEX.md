## What the app does (synthesis)

**MP Server Provider** is a Windows desktop GUI (WPF shell hosting a WebView2-rendered UI, CommunityToolkit.Mvvm MVVM) for installing, configuring, running, and exposing dedicated game servers — a GUI analogue of tools like AMP/LinuxGSM for Windows. Supported games are declared as **data-driven JSON definitions** at `data\providers\json\*.json` (confirmed schema match against `Core.Models.GameDefinition`/`InstallSpec`/`NetworkSpec`/`ArtworkSpec`/`ModsSpec`): FiveM/RedM (CitizenFX), BeamMP, Minecraft Java/Bedrock, 7 Days to Die, ATS, ETS2, GMod, Rust, Unturned, Valheim, PixARK, Cubic Odyssey. Each definition names an **install provider** (`Core.Providers`: `SteamCmdProvider`, `CfxProvider`, `BedrockProvider`, `JavaRuntimeProvider`, `MinecraftJavaProvider`, `BeamMpProvider`, `ManualProvider`, `UrlProvider`), a runtime executable/launch command, a default network port/protocol/query type, and optional mod support.

Core services (`Core.Services`) implement: server process lifecycle (`ServerProcessService`, `ServerRepository`, `ServerState`/`ServerStats`), installation (`InstallService`, `DownloadService`), RCON admin commands (`RconService`), server status polling (`QueryService`), Windows Firewall rule automation (`FirewallService` — backs the "Add Firewall Rule" dialog), external connectivity via **two tunnel mechanisms**: UPnP/NAT-PMP router port mapping (`Open.Nat` dependency, `UpnpResult`) and a bundled **playit.gg** tunnel client (`TunnelService` drives `playit.exe`, downloads it via `PlayitReleasesApi`, maps/unmaps ports, polls discovery), Steam-store metadata/cover-art fetch and caching (`ArtworkCacheService`, ties to `data\cache\artwork\*.jpg`), mod/workshop management (`ModLibraryService`, `WorkshopService`), news feed (`NewsService`/`BuiltInNews`), app settings persistence (`SettingsService`/`AppSettings`), a secret-at-rest helper (`SecretProtector`, almost certainly DPAPI-backed, used for a license key per `LicenseKeyDialog`/`Views.LicenseKeyDialog`), system metrics/drive usage via WMI (`SystemMetricsService`, `SystemSpecs`, `DriveUsage` → explains the `System.Management.dll` dependency), and a de-elevation launcher (`DeElevatedProcess`/`DeElevatedLauncher`) so the app can run elevated (for firewall/NAT work) while spawning game server processes unelevated.

The App-side WPF shell (`MPServerProvider.App.Views`) has pages for Home, Library (install catalog), My Servers (instance list + detail/live stats + RCON/console), Mods, Settings, plus dialogs for adding a custom game, adding a firewall rule, installing a server, manual install, license key entry, and tunnel setup — wired through ViewModels using `[ObservableProperty]`/`[RelayCommand]` (CommunityToolkit.Mvvm), each async handler (`OnInstall`, `OnStart`, `OnStop`, `OnRestart`, `OnMap`, `OnUnmap`, `OnAddRule`, `OnDeleteRule`, etc.) compiled to a C# async state-machine (`<OnX>d__N` nested type) that REA's managed inspector surfaces as a separate type with its own `MoveNext` body, call edges and string literals.

## Decompile fidelity ledger

REA's managed pipeline (`inspect_managed_members`) gives **authenticated, complete, build-local-token-bound** metadata for both assemblies: every TypeDef, field, method signature, IL opcode histogram, call edge (callee name + declaring type), field access, and `ldstr` string literal — all captured losslessly in the exported evidence bundle (`mpserver_evidence_bundle.json`, 9.4 MB, retained in this session). This is **not** decompiled C# source: REA has no managed pseudocode/C# decompiler in this session's tool list (`batch_decompile`/`decompile_jeb_item` target native/Android formats only; `import_managed_reconstruction` is a sink for externally-produced ILSpy/dnSpy output, not a producer). Every per-type `.md` file under this report is therefore a **structural reconstruction**: exact class/field/method shape plus call graph and literal evidence, sufficient to redrive the design and most of the control flow, but not a byte-for-byte restatement of the original source. Async method bodies in particular show only the compiler-generated `AsyncTaskMethodBuilder.Create/Start/get_Task` stub at the declaring method — the real logic is in the paired `<Method>d__N.MoveNext()` state-machine type, which is reported as its own type file in the same namespace folder.

## Fully-resolved vs. opaque

- **Fully resolved (metadata+behavior-by-evidence):** all 91+171 type shapes, all field types, all method signatures, 100% of call edges (9,101 combined) and user strings (946 combined) for both assemblies — exported in `mpserver_evidence_bundle.json`.
- **Config/data layer, directly read (ground truth, not inferred):** all 14 `data\providers\json\*.json` game definitions; `data\servers\*\server.json` per-instance config; cached Steam artwork JPEGs; installed mod jars under `data\mods\`. These should be copied as-is into any rewrite rather than re-derived.
- **Resolved in the follow-up pass (see new files below):**
  - **UI technology is settled: 100% native WPF, not web-hosted.** See `UI_TECHNOLOGY.md`. The single `ManifestResource` is the standard WPF `.g.resources` blob; it was loaded via reflection and all 16 BAML entries were fully decompiled back to readable XAML using WPF's own `Baml2006Reader` → `XamlXmlWriter` pipeline. See `BAML_STRUCTURE.md` and `baml_xaml\*.xaml` (sibling to this report dir) for the full per-screen layout/control inventory. WebView2 is used in exactly one place (`ServerDetailView`'s `TxAdminWeb`, for FiveM/RedM's txAdmin panel) — everything else is native controls.
  - **`SecretProtector` confirmed: plain Windows DPAPI** (`ProtectedData.Protect/Unprotect`, `CurrentUser` scope, static entropy `"MPServerProvider.v1"`). See `SECRET_PROTECTOR.md` for the exact logic and a Rust-port recipe (two options: re-key, or byte-compatible via `windows-rs` `CryptProtectData`/`CryptUnprotectData`).
  - **Native/P-Invoke boundary scan done**: `App.dll` has zero P/Invoke (100% managed). `Core.dll` has exactly 8 P/Invoke imports, all Win32 (`user32`/`kernel32`/`advapi32`), all backing the de-elevation launcher's "duplicate the shell's unelevated token and spawn a process with it" pattern. See `NATIVE_BOUNDARIES.md` for the full list and `windows-rs` equivalents.
- **Still opaque / needs runtime observation if higher fidelity is needed:**
  - Exact branch/loop structure and literal control flow inside method bodies (REA reports opcode histograms and anchors, not a full CFG/pseudocode render) — rebuild from signatures + call edges + naming, verify against runtime behavior where it matters (e.g. `QueryService`'s wire protocol per game, `RconService` packet format, `playit.gg` protocol in `TunnelService`).
  - Some markup-extension values in the recovered XAML (`{StaticResource ...}` etc.) round-trip as their CLR type name rather than curly-brace shorthand — cosmetic, the resource key is still present as a child node.

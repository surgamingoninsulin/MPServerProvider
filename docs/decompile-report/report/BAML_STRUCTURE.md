# BAML → XAML Reconstruction

All 16 compiled BAML resources in `MPServerProvider.App.g.resources` were decompiled to **full, readable XAML** (not just metadata) by loading the real assembly in a throwaway PowerShell/.NET host and driving WPF's own internal `System.Windows.Baml2006.Baml2006Reader` → `System.Xaml.XamlXmlWriter` pipeline via reflection (script: `..\..\baml2xaml.ps1`, one level above `report\`). This is the actual compiled node stream re-serialized as XML — element tree, nesting, attributes, named elements (`x:Name`), and resource/style references are all present. Output files: `baml_xaml\*.xaml` (15 views + `app.xaml` + `themes_theme.xaml`).

Minor cosmetic caveat: some markup extensions (`{StaticResource ...}`, converters) round-trip showing their CLR type name as the attribute value instead of the original `{...}` shorthand text; the underlying resource key/binding is still present as a child element in the raw node stream, just not re-abbreviated to curly-brace shorthand. Not a fidelity loss — a trivial textual normalization pass would restore the shorthand if desired.

## Per-view named-element inventory (control surface for the rewrite)

- **app.xaml** — Application root, StartupUri etc., no named elements (expected).
- **themes_theme.xaml** — shared ResourceDictionary (colors/brushes/control styles/templates used everywhere else); no named elements (expected — it's all keyed resources).
- **views_mainwindow.xaml** — shell chrome: `nav` (sidebar), `NavHome`, `NavLibrary`, `NavServers`, `NavMods`, `NavSettings` (nav buttons), `PageHost` (ContentControl/Frame for page navigation), `MaxRestoreButton` (custom chrome — confirms a borderless/custom-titlebar window with its own min/max/close).
- **views_splashwindow.xaml** — `Progress`, `PercentText`, `StatusText` (startup splash with progress bar).
- **views_homepage.xaml** — dashboard: `PlayersStat`, `UptimeStat`, `ServersShortcutText`, `ModsShortcutText`, `NewsHost`/`NewsScroller` (news feed panel).
- **views_librarypage.xaml** — install catalog: `SearchBox`/`SearchHint`, `GenreChips` (filter chips), `CardsHost` (game card grid), `CountText`.
- **views_myserverspage.xaml** — instance list: `SearchBox`/`SearchHint`, `ServerList`, `ActiveCountText`, `EmptyState`, `DetailHost` (hosts `ServerDetailView` for the selected server).
- **views_serverdetailview.xaml** — the richest view, tabbed: `TabConsole`/`TabFiles`/`TabMods`/`TabResources`/`TabSettings`/`TabTxAdmin`. Panels: `ConsolePanel` (`ConsoleOutput`, `ConsoleScroll`, `CommandBox` — live RCON/console), `FilesPanel` (`FilesList`, `FileEditorPanel`/`FileEditorBox`/`EditorFileName`/`EditorStatus`, `NewFileButton` — in-app file browser/editor for the server install dir), `ModsPanel` (`InstalledModsList`, `LibraryModsList`), `ResourcesPanel` (`CpuBar`/`CpuText`, `RamBar`/`RamText`, `PlayersText`, `UptimeText` — live stats), `SettingsPanel` (`SettingPort`, `SettingRamMin/Max`, `SettingStartCommand`, `SettingStopCommand`, `SettingAutoRestart`, `SettingDescription`), `TxAdminPanel` (`TxAdminWeb` — the WebView2, `TxAdminPlaceholder`, `TxAdminStatusText`), plus header `NameText`/`GameText`/`StatusBadge`/`StatusText`/`ConnectionText`, and `StartButton`/`StopButton`.
- **views_modspage.xaml** — `KeywordBox`/`KeywordHint`, `GameFilter`/`GameChecks` (per-game filter checkboxes), `ModsHost`, `ModsEmptyState`, `FilterHeader`.
- **views_settingspage.xaml** — app settings + system specs panel: `SettingStartOnBoot`, `SettingStartMinimized`, `SettingRestoreServers`, `SettingNewsAutoScroll`; `SpecCpu`/`SpecGpu`/`SpecRam`/`SpecOs` (static system info), `CpuBar`/`CpuText`/`RamBar`/`RamText` (live), `DriveCombo`/`DiskUsageBar`/`DiskUsageText`/`DiskUsageCaption`/`GameFilesBar`/`GameFilesText`/`GameFilesCaption` (per-drive disk usage breakdown), `InstallPathText`, `ActiveServersText`, firewall rules list `RulesHost`/`NoRulesText`.
- **views_addcustomgamedialog.xaml** — "Add custom game" form with a source-type switch: `TypeNew`/`TypeImport` (+ `TypeNewBorder`/`TypeImportBorder`), `InstallSource` combo driving visibility of `SteamPanel` (`SteamUserBox`/`SteamPassBox`/`AnonymousCheck`/`CredentialsPanel`/`AppIdBox`), `SourceJson`, `SourceSteam`, `JsonFieldsPanel`, `FolderPickerPanel`/`FolderBox`, plus `NameBox`, `ImageBox`, `ExecBox`/`ExecPanel`, `ArgsBox`, `StopBox`, `PortBox`, `ProtocolCombo`, `ModType` (+ `ModTypeNone`/`ModTypeMods`/`ModTypePlugins`/`ModTypeAddons`), `ModsBox`, `WorkshopBox`, `FetchButton`, `AddButton`. This is the UI for hand-authoring one of the `data\providers\json\*.json` definitions.
- **views_addfirewallruledialog.xaml** — `NameBox`/`NameHint`, `PortBox`/`PortHint`, `ProtocolCombo`.
- **views_installserverdialog.xaml** — install wizard with form state + progress state: `FormPanel` (`NameBox`, `PortBox`, `VariantCombo`/`VariantPanel`, `VersionCombo`, `RamMinBox`/`RamMinPanel`, `RamMaxBox`/`RamMaxPanel`, `EulaCheck`, `ManualFolderBox`/`ManualFolderPanel`, `NoteBox`/`NoteText`) vs. `ProgressPanel` (`ProgressBarControl`, `ProgressPercent`, `ProgressStatus`, `ProgressTitle`), `CancelInstallButton`/`InstallButton`.
- **views_manualinstalldialog.xaml** — `NameBox`, `FolderBox`, `PortBox`, `InstallButton`.
- **views_licensekeydialog.xaml** — `KeyBox`/`KeyHint` (single field, feeds `SecretProtector`).
- **views_tunneldialog.xaml** — tabbed `TabUpnp`/`TabPlayit`: UPnP tab (`UpnpPanel`, `UpnpAddressBox`/`UpnpAddressText`, `UpnpResult`, `MapButton`/`UnmapButton`, `ServerCombo`), playit.gg tab (`PlayitPanel`, `PlayitOutput`/`PlayitScroll`, `StartAgentButton`/`StopAgentButton`).

## Rewrite implication
This gives near-complete layout/control fidelity for all 16 screens without needing runtime screenshots — build each Rust view from its named-element list + the full recovered XAML tree in `baml_xaml/`, matching control types, nesting and panel visibility toggles 1:1.
